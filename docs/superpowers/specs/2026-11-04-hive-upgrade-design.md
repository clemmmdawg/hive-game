# Hive Upgrade — Bugs, Neon Bestiary Art, Juice, PWA + History/Replay

Date: 2026-11-04 · Branch: `upgrade/juice-art-pwa`

## Intent

Make the existing pass-and-play / online Hive PWA feel like a polished mobile game:
readable at a glance on a phone, satisfying to play (motion, sound, haptics), installable,
and reviewable after the game. Fix any real rules/logic bugs first.

**User said:** upgrade and fix the game; extra juice, new art, bug fixes, maybe features.
Chosen packs: Neon Bestiary art, Juice, PWA + history/replay. No AI opponent this round.
Art: species-coloured glyph on a dark tile, player shown by a thick neon rim.

**Bar:** each phase is built by a builder agent and gated by a separate critic agent that
runs tests and inspects the game in a real browser (phone 390×844 @ DPR 3 and desktop
1280×800). A phase is done only when the critic signs off with no open issues and
`npm test` + `npm run check` are green.

**Constraints (unchanged):** no build step, no framework, vanilla ES modules; `game.js`
stays DOM-free and importable on the server; direction array order in `game.js` is
untouched; user CSS overrides listed in CLAUDE.md are preserved; reduced-motion honoured.

## Phase 0 — Bug fixes & hardening

Input: the bug-hunt report (Appendix A). For every confirmed bug:
- a failing regression test in `test/` first, then the minimal fix;
- server and client both use the fixed `game.js` (no duplicated logic).
`npm install` precondition documented in README (`ws` dependency).

## Phase 1 — Neon Bestiary art

**sprites.js** is redrawn. Same public API (`spriteSVG`, `drawSprite`, `data-sprite`),
same 64×64 grid, head up. New recipe:
- bold filled silhouettes (body mass fill at ~35–45% ink alpha + solid ink outline),
  plus a few interior details (wing veins, elytra seam, ladybug spots, pillbug segments,
  spider abdomen mark, queen crown). Must read as the species at 28 px.
- Each species has a **species colour** exported as `SPECIES_COLOR[type]`:
  Queen gold `#ffd23f`, Beetle violet `#b07cff`, Grasshopper lime `#a6ff3d`,
  Ant blue `#4d8dff`, Spider orange `#ff7a3d`, Mosquito silver `#d8dcef`,
  Ladybug red `#ff4040`, Pillbug teal-green `#2fe0a8`. (No species within
  ΔE ≈ 25 of `--p1` `#ff2d78` or `--p2` `#00f5ff`; critic verifies by eye at phone size.)

**Board tiles (board.js):** dark bevelled hex face (subtle radial gradient), species
glyph in its species colour with soft glow, **thick player-colour rim** (outer glow +
inner line) so ownership is unambiguous. Beetle stacks: each buried layer drawn as a
visibly offset darker slab beneath (stepped 3D), height badge `×N` on top tile; buried
species shown as small coloured sprite badges as today. Ghosts, selection ring,
throw rings, last-move marker keep working and remain distinguishable from rims.

**DOM UI:** tray pieces, reserve strip, tooltips, stack inspector, How-to-Play, menu
expansion cards all use species colours for the glyph and player colour for the frame.
CSS tokens `--sp-queen`… added to `:root`.

**Icons:** `assets/icons/icon.svg` (queen glyph on hex, neon) and rasterised PNGs
192, 512, 512-maskable, apple-touch 180, favicon. Generated by a committed node script
`scripts/make-icons.mjs` using Playwright (dev-only, not runtime).

## Phase 2 — Juice

**`getMovePath(state, from, to) → string[]`** (pure, in game.js): the hex sequence
the piece travels, inclusive of `from` and `to`.
- Ant/Queen/Spider/Pillbug-move: shortest legal sliding path (BFS over the same slide
  graph used for move generation; spider = an exact 3-step path).
- Grasshopper: straight line of hexes jumped over.
- Beetle / Mosquito-as-beetle: `[from, to]` with height info for arc.
- Ladybug: a valid 3-step path (up, across, down).
- Mosquito: path of the copied ability that yields `to`.
- Throws: `[from, pillbugHex, to]`.
Unit-tested for every species.

**Animation (board.js):** `board.animateMove({from, to, path, kind, piece})` tweens a
ghost piece along the path (slide = constant-speed eased polyline; hop/climb = parabolic
arc with scale-up; throw = high arc; place = drop-in from above with squash). During the
tween the destination stack draws without the moving top piece. ~120 ms per hex step,
capped at 700 ms total. Input stays responsive; a new action completes any running tween.
Online moves from the opponent animate the same way (path computed from the previous
state). Undo does not animate.

**Impact FX:** landing ripple ring in the player colour + 10–16 spark particles in the
species colour; 2–3 px camera nudge on beetle-climb/throw landings. Particle system in
board.js, capped, culled when finished.

**audio.js:** WebAudio synth, no asset files. Sounds: select, deselect, place, slide,
hop, climb, throw, invalid, turn, queen-danger, win, lose/draw. AudioContext created on
first user gesture. Mute toggle in the ☰ menu (and `M` key), persisted in localStorage.
**Haptics:** `navigator.vibrate` short pulses on place/move landing, longer on queen
danger and win; no-op where unsupported; haptics follow the same mute toggle.

**Queen danger meter:** six pips drawn around each placed queen (filled per occupied
neighbour). 4 → amber pulse; 5 → red pulse + `queen-danger` sound + HUD status
"P1 QUEEN IN DANGER" once per transition. Pips also shown in the HUD player chips.

**Win sequence:** last move plays at 0.4× speed, white shockwave from the surrounded
queen, brief board dim, then the existing confetti + win card (delay ≤ 1.6 s).

**Reduced motion:** tweens become instant, no particles/shake/shockwave; sounds kept.

## Phase 3 — PWA + History/Replay

**PWA:** `manifest.json` (name, short_name "HIVE", theme `#05050f`, display standalone,
portrait-any, icons from Phase 1). `sw.js`: precache list of app shell (versioned cache
name `hive-v<N>`), cache-first for shell, network-only for `/ws`, stale caches deleted
on activate, `skipWaiting` via message on user-accepted update toast ("Update ready —
reload"). Registered from app.js only on http(s) origins. `<link rel=manifest>`,
apple meta tags, theme-color. Static allowlist already contains manifest/sw/favicon;
add `/assets/icons/`. Lighthouse-style installability check by the critic (manifest
parsed, SW controls page, offline reload of a local game works).

**Notation (`js/notation.js`, pure):** standard Hive notation. Piece ids `wQ`, `wA1`…
(white = P1, black = P2, numbered in placement order per type); position relative to
a neighbouring piece (`wA1 -bQ`, `bS1 /wA1`, `wB1 bQ` for climbing); first move is the
bare piece; `pass`. Throws notated as the thrown piece's move. Round-trip tested:
`toNotation(prevState, action)` for every action type.

**History:** app keeps `moveLog: [{action, notation, player, turnNumber}]`. Undo pops.
Saved in local save (local-save VERSION bump with v1 migration → empty log). Online:
built client-side from successive GAME_STATE diffs via `describeLastMove`, plus a
`history` array in the server's GAME_STATE so reconnecting clients get it.

**Move list panel:** "MOVES" entry in ☰ opens a slide-up sheet listing numbered moves
with sprite + notation; tapping a row previews that position (read-only) with a
"Back to game" pill.

**Replay:** win screen gains REPLAY. Replay mode hides tray, shows a scrubber bar
(⏮ ◀ ▶/❚❚ ▶ ⏭, slider, move label), steps animate with Phase 2 paths, autoplay
1 move / 900 ms. "COPY MOVES" copies the notation list. Esc / ✕ exits back to the
win card.

## Testing

- New suites: `paths.test.js` (getMovePath all species + throws), `notation.test.js`,
  `history.test.js` (undo/save migration), `static.test.js` additions (icons dir, sw).
- Each critic writes a Playwright script under the scratchpad that seeds positions via
  localStorage / UI clicks, screenshots phone + desktop, checks for console errors.
- Final: full regression run + an end-to-end local game played to a win via the UI.

## Out of scope

AI opponent, clock, spectator mode, persistent online rooms.
